## How to launch

### Prerequisites (one-time setup)

**Windows host:**
```powershell
# 1. Download zenohd.exe from github.com/eclipse-zenoh/zenoh/releases
#    Extract to a folder you can run from, e.g. C:\tools\zenoh\zenohd.exe

# 2. Install Python deps for the launcher script
pip install paramiko
```

**WSL:**
```bash
pip install eclipse-zenoh
# Then build the workspace (includes the new relay node)
cd /workspaces/AutoWarehouseBot
colcon build --packages-select embedded
source install/setup.bash
```

**Pi:**
```bash
pip install eclipse-zenoh
cd ~/AutoWarehouseBot
colcon build --packages-select embedded
source install/setup.bash
```

---

### Launch option A — one command from Windows (recommended)

Edit the config block at the top of `launch_warehouse.py` to set your IPs,
then run:

```powershell
python launch_warehouse.py
```

This starts zenohd, SSHs into the Pi to start the relay + robot_bringup,
and starts the WSL relay + hardware stack — all in one terminal with
color-coded per-machine output.

Press `Ctrl+C` to shut everything down cleanly.

---

### Launch option B — manual, machine by machine

**Step 1 — Windows: start the router**
```powershell
.\zenohd.exe
# Keep this terminal open. It is the backbone of the network.
```

**Step 2 — Pi: start hardware + relay**
```bash
# In one terminal on the Pi:
source /opt/ros/kilted/setup.bash
source ~/AutoWarehouseBot/install/setup.bash
ros2 launch embedded robot_bringup.launch.py

# In a second terminal on the Pi:
source /opt/ros/kilted/setup.bash
source ~/AutoWarehouseBot/install/setup.bash
ros2 launch embedded zenoh_relay.launch.py role:=pi router_ip:=<WINDOWS_WIFI_IP>
```

**Step 3 — WSL: start Nav2 + relay**
```bash
# In one terminal in WSL:
source /opt/ros/kilted/setup.bash
source /workspaces/AutoWarehouseBot/install/setup.bash
ros2 launch navigation hardware.launch.py

# In a second terminal in WSL:
source /opt/ros/kilted/setup.bash
source /workspaces/AutoWarehouseBot/install/setup.bash
ros2 launch embedded zenoh_relay.launch.py role:=laptop router_ip:=<WINDOWS_WIFI_IP>
```

**Step 4 — verify bridge is active**
```bash
# In WSL — should see Pi's laser scan arriving:
ros2 topic echo /scan --once

# In WSL — send a command and verify it reaches the Pi:
ros2 topic pub /cmd_vel geometry_msgs/msg/TwistStamped "{twist: {linear: {x: 0.0}}}" --once
```

## What gets bridged

| Topic      | Direction    | Why |
|------------|--------------|-----|
| `/cmd_vel` | WSL → Pi     | Nav2 on WSL drives the motors on Pi |
| `/odom`    | Pi → WSL     | Wheel odometry feeds Nav2 EKF |
| `/scan`    | Pi → WSL     | LiDAR feeds Nav2 AMCL localisation |
| `/imu/data`| Pi → WSL     | IMU feeds Nav2 EKF |

## Teammate going native (no Docker)

The Zenoh relay is unaffected — it was designed to run natively from the start.
Docker was never part of the relay architecture. If a teammate drops the dev container
and runs ROS2 natively on their machine, they only need to do this once:

```bash
# Clone repo (or pull latest)
git clone <repo> ~/AutoWarehouseBot
cd ~/AutoWarehouseBot/ros2_ws
source /opt/ros/kilted/setup.bash
colcon build --packages-select embedded

# Set up zenoh venv
python3 -m venv ~/zenoh_venv --system-site-packages
~/zenoh_venv/bin/pip install eclipse-zenoh

# Launch relay (role=laptop, pointing at Felix's Windows machine)
source ~/zenoh_venv/bin/activate
source /opt/ros/kilted/setup.bash
source ~/AutoWarehouseBot/ros2_ws/install/setup.bash
ros2 launch embedded zenoh_relay.launch.py role:=laptop router_ip:=104.194.115.245
```

Their workspace path (`~/AutoWarehouseBot/ros2_ws`) differs from Felix's WSL path (`~/ros2_ws`)
— this only matters for their own terminal, not for `launch_warehouse.py` which only
controls Felix's WSL.
